# i18n (`src/presentation/i18n`)

```ts
import { useTranslation } from "@presentation/i18n";      // or default from "@presentation/i18n/useTranslation"
const { t } = useTranslation();
<Text.Title value={t("financial.accounts.title")} />
```

- Outside React: `translate(key, params)` from `@presentation/i18n`.
- Locale: `useTranslationLocale()` → `{ getLocale, changeLocale, availableLanguages }`.
- Keys are **type-checked** against `translations/en-US` (`TranslationKeys` = recursive dotted keys). Missing key in en-US = type error.
- Never import `react-i18next` outside `i18n/react-i18n/` (lint error).

## Files

```
translations/
  index.ts                 { "en-US", "pt-BR" }, fallback en-US
  en-US/index.ts           { translation: { configurations, dashboard, errors, family, financial, login, stock } }
  en-US/<namespace>.ts     const financial = { accounts: { title: "Accounts", ... }, categories: {...} }; export default financial;
  pt-BR/...                same shape, Portuguese values
```

## Adding text

1. Add key to `en-US/<namespace>.ts` **and** `pt-BR/<namespace>.ts` (same path, keys alphabetical).
2. New namespace: create both files and register in both `index.ts` files.
3. Common keys per feature: `title`, `routeTitle`, `loading`, `add`, `save`, `cancel`, `addNewX`, `editX`, `deleteAlertTitle`, `deleteAlertMsg`, `deleteBtn`, `<field>Required`.
4. Validation messages are i18n keys too. Some older `useForm` hooks hard-code English; don't copy them.
5. MVVM split (see `presentation.md`): **the View calls `t()`**. ViewModel hooks and UI models return `TranslationKeys` (imported from `@presentation/i18n/types`) for text that depends on state or data, such as `titleKey`, `ownerTypeLabelKey` and form error keys. The only exception is imperative UI (`Alert.alert`, `window.confirm`, `navigation.setOptions` titles), where the hook calls `useTranslation()` itself.
